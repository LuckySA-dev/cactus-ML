## ส่วนที่ 2: ปัญหาที่แก้

- กระบองเพชรแคระเป็นไม้เลี้ยงยอดนิยมในไทย มีขายตามฟาร์ม ตลาดต้นไม้ และออนไลน์ แต่**หลายสกุลหน้าตาคล้ายกันมาก**
  สำหรับมือใหม่ และป้ายชื่อที่ร้านมักไม่มีหรือเขียนผิด
- **แต่ละสกุลต้องดูแลต่างกัน** เช่น บางสกุลชอบแดดจัด บางสกุลต้องแสงกรอง บางสกุลเน่าง่ายถ้ารดน้ำเกิน
  ดูแลผิดวิธีทำให้ต้นเน่า ไหม้แดด หรือไม่โต
- เป้าหมาย: ให้ผู้ใช้**ถ่ายรูปด้วยมือถือ** แล้วรู้ชื่อสกุล/ชนิด พร้อมวิธีดูแลที่เหมาะกับต้นนั้น

## ส่วนที่ 3: ระบบทำอะไร (ภาพรวม)

```
ภาพจากมือถือ (JPG / PNG / WEBP / HEIC)
        ↓ หมุนตาม EXIF + Resize 256 → CenterCrop 224
โมเดล CNN (DenseNet-121 เป็นค่าเริ่มต้น)
        ↓ ทาย 20 คลาสย่อย แล้วรวมความน่าจะเป็นขึ้นเป็น 7 สกุล
ความมั่นใจ ≥ 60% ?
   ├─ ใช่  → ป้ายชื่อ: สกุล + ชนิด + % ความมั่นใจ → วิธีดูแล (น้ำ / แสง / ดิน / ข้อควรระวัง + แหล่งอ้างอิง)
   └─ ไม่ใช่ → "ไม่แน่ใจ" + เคล็ดลับถ่ายรูปใหม่ (ไม่แนะนำวิธีดูแล เพราะแนะนำผิดสกุลอาจทำให้ต้นเสีย)
```

ระบบมี 2 ส่วนแยกกันชัดเจน
1. **ML:** image classification ภาพ → สกุล + ชนิด + ค่าความมั่นใจ (ส่วนที่ให้คะแนนวิชา)
2. **Rule-based:** lookup วิธีดูแลจาก `care_rules/care_rules.json` ด้วยสกุล/ชนิดที่ทายได้ (ไม่ใช่ ML)

**เป้าหมายที่ตั้งไว้** (อ้างอิงงานวิจัยจำแนกกระบองเพชร)
- Test accuracy ระดับสกุล **≥ 91%** (baseline จากงานวิจัยอ้างอิง)
- Gap ระหว่าง test กับภาพถ่ายจริง **ไม่เกิน 9.86%** (ค่า gap ของงานวิจัยอ้างอิง)

### 5.3 กัน data leakage (สำคัญ)
- **ต้นเดียวกันอยู่ split เดียวกันเสมอ** (แบ่งตาม plant_id) ทีมถ่ายต้นเดียวหลายมุม ถ้าภาพต้นเดียวกันอยู่ทั้ง train
  และ test ตัวเลขจะสูงเกินจริง
- **ตัดภาพซ้ำด้วย perceptual hash (phash) ก่อนแบ่ง** เพราะ dataset หลายแหล่งดึงภาพซ้ำกันมาจาก iNaturalist
- ตรวจอัตโนมัติซ้ำหลังแบ่ง: ไม่มีต้นหรือภาพซ้ำ (รวมภาพเกือบซ้ำ phash ห่าง ≤ 4) ข้าม split เลย

### 5.4 Quality control (QC) 4 ชั้น
1. **สุ่มตรวจ 10% ต่อคลาส** ด้วยตา → พบ label ผิดสกุล 0 จาก 280 ภาพ
2. **ให้โมเดลช่วยคัดภาพน่าสงสัย** (5-fold out-of-fold prediction แบบ confident learning) ทำ 4 รอบ
   → คนดูเฉพาะภาพที่โมเดลไม่เชื่อ label
3. **ตรวจด้วยตาครบทุกภาพที่เหลือ** 3,845 ภาพ (241 แผ่นภาพรวม แผ่นละ 16 ภาพ)
4. **ตรวจความถูกต้องอัตโนมัติ 100%:** label ตรงโฟลเดอร์, ชนิดตรงสกุล, ไฟล์เปิดได้, ไม่มี leakage

ผลการตัดทิ้ง (526 ภาพ): ดอกบังต้น/ไม่เห็นต้น 213 · หลายสกุลในภาพเดียว 178 · เบลอ/มืด/ต้นเล็กเกิน 97 ·
**label ผิด 38** (ส่วนใหญ่ชนิดผิด ผิดสกุลจริงน้อยมาก)
ภาพที่ปลูกลงดิน (ไม่อยู่ในกระถาง) 839 ภาพ **ตัดสินใจเก็บไว้เทรน** เพราะลักษณะต้นยังชัด

ข้อสังเกตจาก iNaturalist: ต้นปลูกในกระถางถูกติดธง captive และไม่มีวันเป็น research grade
จึงรับทุก quality grade ที่มีคนยืนยันชื่อ ≥ 1 คน แล้วใช้ QC ของทีมแทน

## ส่วนที่ 6: โมเดล

เทียบ 6 สถาปัตยกรรม (CNN, ImageNet pretrained) **ใช้ hyperparameter ชุดเดียวกันทั้งหมด** เพื่อเทียบอย่างยุติธรรม

| โมเดล | ชื่อใน timm | พารามิเตอร์ | เวลาทาย CPU/ภาพ | ใช้ในแอป |
|---|---|---|---|---|
| DenseNet-121 | densenet121 | 7.0M | 70 ms | อันดับ 1 (ค่าเริ่มต้น) |
| EfficientNet-B3 | efficientnet_b3 | 10.7M | 49 ms | อันดับ 2 |
| EfficientNetV2-B0 | tf_efficientnetv2_b0 | 5.9M | 34 ms | อันดับ 3 |
| MobileNetV3-L | mobilenetv3_large_100 | 4.2M | 18 ms | |
| ResNet34 | resnet34 | 21.3M | 30 ms | |
| ResNet50 | resnet50 | 23.5M | 59 ms | |

- DenseNet-121 / EfficientNet-B3 / ResNet34 เพิ่มตามงานวิจัยอ้างอิง (งานหนึ่ง DenseNet-121 ชนะ, งานกระบองเพชรใช้ ResNet34)
- หัว classifier เริ่มที่ศูนย์ (zero-init) ทุกโมเดลเริ่ม loss เท่ากัน (ln 20) ไม่เอียงข้างใด
- แอปเลือก 3 อันดับแรกตามความแม่นยำระดับชนิดบน test และใช้ seed ที่ validation ดีที่สุดของแต่ละโมเดล

## ส่วนที่ 7: การเทรน

### 7.1 สูตรเทรน

| หัวข้อ | ค่า |
|---|---|
| จำนวน run | 6 โมเดล × 3 seeds (42, 43, 44) = **18 run** + ช่วงจูน 30 run · เวลาเทรนรวม ≈ 6.4 ชั่วโมง |
| ขนาดภาพ / batch | 224 × 224 px · batch 64 |
| Stage 1 | freeze backbone เทรนเฉพาะหัว 10 epochs · AdamW lr 0.001 · BatchNorm ของ backbone อยู่ใน eval mode |
| Stage 2 | fine-tune ทั้งตัว สูงสุด 40 epochs · AdamW lr backbone 3e-4 / หัว 3e-3 · Cosine annealing · early stopping patience 8 |
| epoch ที่ใช้จริง | stage 2 เฉลี่ย 36 epochs (checkpoint ที่ดีสุดเฉลี่ย epoch 30) |
| Optimizer | AdamW · weight decay 1e-4 |
| Loss | CrossEntropy + label smoothing 0.1 (ทำให้ค่าความมั่นใจเชื่อถือได้ ใช้กับเกณฑ์ 60%) |
| Regularization | dropout 0.3 ก่อนหัว · **EMA ของน้ำหนัก** (decay 0.998) ใน stage 2 |
| Mixed precision | เทรน bfloat16 autocast · ประเมินผล fp32 (ค่าความมั่นใจตรงกับแอป) |
| เลือก checkpoint | **macro F1 บน validation** สูงสุด (ไม่ใช่ accuracy) |
| ทำซ้ำได้ | ตั้ง seed ทุกที่ + deterministic algorithms → เทรนซ้ำได้ผลเดิมเป๊ะ (ตรวจแล้ว) |

### 7.2 การจูน (ทุกครั้งดู validation เท่านั้น)
- **learning rate:** ค่าเดิม 1e-5/1e-4 ต่ำเกิน → จูนเป็น 3e-4/3e-3 → val F1 **0.890 → 0.930**
- **EMA + augmentation แรง:** val F1 **+2.1 จุด** ชนะทุก seed → ใช้เป็นสูตรหลัก
  ผล test ดีขึ้นทุกโมเดล +0.9–1.9 จุด (สกุล) / +1.7–3.1 จุด (ชนิด)
- **ลองแล้วไม่ช่วย (ผลลบ รายงานตรง ๆ):** test-time augmentation, ensemble หลายโมเดล,
  ถ่วงน้ำหนักคลาส / undersample คลาสใหญ่
- ข้อสรุปจากการจูน: error ราวครึ่งหนึ่งมาจากภาพไม่ดี/label ผิด → **คุณภาพข้อมูลคือคันโยกหลัก** จึงลงแรงกับ QC

### 7.3 Data augmentation (ใช้กับ train เท่านั้น ตามลำดับ)

| ขั้น | ทำอะไร | ทำไม |
|---|---|---|
| 1. RandomResizedCrop | ครอป 35–100% ของภาพ แล้วย่อเป็น 224×224 | ภาพจริงถ่ายไกล ต้นเล็กในเฟรม หรือใกล้จนเห็นบางส่วน |
| 2. RandomHorizontalFlip | กลับซ้าย–ขวา (p = 0.5) | ต้นสมมาตรซ้าย–ขวา · **ไม่กลับบน–ล่าง** เพราะต้นมีบน–ล่างชัด |
| 3. RandomRotation | หมุน ±20° | ถือมือถือเอียง |
| 4. RandomPerspective | บิดมุมกล้อง distortion 0.2 (p = 0.3) | ผู้ใช้มักก้มถ่ายจากด้านบนหรือเฉียง |
| 5. GaussianBlur | kernel 5, σ 0.1–2 (p = 0.2) | ภาพมือถือโฟกัสพลาด มือสั่น |
| 6. ColorJitter | สว่าง ±25% · คอนทราสต์ ±25% · อิ่มสี ±20% · hue ±0.02 | แสงต่างกันแต่ละที่ · **hue น้อยมาก** เพราะสีเป็นลักษณะของบางชนิด (ยิมโนหัวสี) |
| 7. RandomErasing | ลบสี่เหลี่ยมสุ่ม (p = 0.25) | ไม่ให้พึ่งจุดเดียว เช่น ดอก |
| 8. Normalize | mean/std จาก pretrained weights ของ timm | ให้ input ตรงกับตอน pretrain |

ชุด validation/test/แอป: Resize 256 → CenterCrop 224 → Normalize อย่างเดียว
ภาพประกอบ: `reports/figures/augment.png` (แผนที่รวมทุกขั้น) และ `reports/figures/augment_<ขั้น>.png` (รายขั้น)

## ส่วนที่ 8: ผลลัพธ์

### 8.1 เทียบ 6 โมเดล (ค่าเฉลี่ย ± SD จาก 3 seeds · test 750 ภาพ · ภาพจริง 107 ภาพ)

| โมเดล | สกุล · test | ชนิด · test | สกุล · ภาพจริง | ชนิด · ภาพจริง | Gap |
|---|---|---|---|---|---|
| **DenseNet-121** | 95.8 ± 0.3% | **91.0 ± 0.5%** | 84.4 ± 1.9% | 69.4% | 11.3% |
| **EfficientNet-B3** | **95.9 ± 0.3%** | 90.4 ± 0.4% | **86.6 ± 2.2%** | 71.7% | 9.3% |
| **EfficientNetV2-B0** | 95.1 ± 0.2% | 89.8 ± 0.5% | 84.7 ± 0.5% | 71.4% | 10.4% |
| MobileNetV3-L | 94.6 ± 0.1% | 89.0 ± 0.9% | 83.8 ± 2.4% | 69.4% | 10.8% |
| ResNet34 | 93.4 ± 0.7% | 88.0 ± 0.7% | 84.7 ± 1.4% | 68.4% | 8.7% |
| ResNet50 | 93.5 ± 0.5% | 87.7 ± 0.4% | 82.2 ± 1.6% | 68.4% | 11.3% |

**ข้อความหลักสำหรับสไลด์**
- **ผ่านเป้า test accuracy ≥ 91% ทุกโมเดล** ดีที่สุด 95.9% (EfficientNet-B3) · DenseNet-121 ทายชนิดได้ 91.0%
- 3 อันดับแรกต่างกันไม่ถึง 1 จุด ส่วนใหญ่ไม่ต่างอย่างมีนัยสำคัญ (McNemar test)
- F1 รายสกุลของ DenseNet-121 (test, seed 42): แอสโตรไฟตัม 0.98 · หูกระต่าย 0.98 · ยิมโน 0.96 · แมม 0.96 ·
  ถังทอง 0.95 · เอคคินอปซิส 0.95 · พาโรเดีย 0.91 (อ่อนสุด)

### 8.2 ภาพจริงจากฟาร์ม และ Gap
- **Gap = test − ภาพจริง** คือตัวชี้วัด generalization (ใช้กับภาพในชีวิตจริงได้ดีแค่ไหน)
- EfficientNet-B3 (9.3%) และ ResNet34 (8.7%) **ต่ำกว่างานวิจัยอ้างอิง (9.86%)** · อีก 4 ตัวสูงกว่าเล็กน้อย (10.4–11.3%)
- เหตุที่ gap กว้างขึ้นหลัง QC: test สะอาดขึ้น (ตัดภาพดอกบังต้น/เบลอที่เคยทำให้ test ต่ำ) และชุดภาพจริงมีแค่ 107 ภาพ
  ตัวเลขแกว่งได้ราว ±3 จุด
- ภาพจริงระดับชนิดยังยาก (68–72%) เป็นจุดที่ต้องพัฒนาต่อ

### 8.3 คลาสที่ยาก (ระดับชนิด)
F1 ต่ำสุด: พาโรเดียสปีชีส์อื่น 0.50 · ยิมโนด่าง 0.67 (มีภาพแค่ 60 ภาพ) · พาโรเดีย magnifica 0.74 ·
เอคคินอปซิสสปีชีส์อื่น 0.75 · กลุ่ม "สปีชีส์อื่น" ยากเพราะรวมหลายชนิดไว้ด้วยกัน
ความสับสนที่คาดไว้ตั้งแต่ pilot: เอคคินอปซิส ↔ แมมมิลาเรีย / ยิมโน (เป็นผลการทดลอง ไม่ใช่บั๊ก)

### 8.4 เกณฑ์ความมั่นใจ (ทำให้แอปไว้ใจได้)
- ความมั่นใจต่ำกว่า **60%** → แอปตอบว่า "ไม่แน่ใจ" แทนการเดา และไม่แนะนำวิธีดูแล
- DenseNet-121 บน test: **ตอบได้ 92.4% ของภาพ และถูก 98.0% ในส่วนที่ตอบ** ภาพที่เหลือแอปขอให้ถ่ายใหม่

### 8.5 อธิบายผลด้วย Grad-CAM
- แสดงส่วนของภาพที่โมเดลใช้ตัดสินใจ (แบบ spotlight หรี่ส่วนที่ไม่ใช้)
- พบว่าโมเดลดูที่**ตัวต้น ไม่ใช่กระถางหรือพื้นหลัง**
- พบว่า**ดอกเป็น cue แรง** (ดอกใหญ่ทำให้ทายผิดได้) → เป็นเหตุผลที่ใส่ RandomErasing และตัดภาพดอกบังต้นใน QC
  หลังใช้สูตรใหม่ ภาพยิมโนดอกใหญ่ที่เคยผิด ทั้ง 3 โมเดลทายถูกและดูที่ลำต้น

## ส่วนที่ 9: ระบบที่ใช้งานได้จริง

### 9.1 เว็บแอป (Streamlit) — 2 หน้า
**หน้า "ทายชื่อ + วิธีดูแล"** (ผู้ใช้ทั่วไป)
- อัปโหลดรูป (รองรับ HEIC จาก iPhone หมุนตาม EXIF) หรือถ่ายจากกล้อง (เปิดกล้องเมื่อกดเท่านั้น)
- ผลแสดงเป็น **การ์ดป้ายปักกระถาง**: ชื่อไทย + ชื่อวิทยาศาสตร์ + ชนิด + ความมั่นใจเป็นคำ (มั่นใจสูง ≥ 85% /
  ค่อนข้างมั่นใจ ≥ 60% / ไม่แน่ใจ)
- **วิธีดูแล 3 การ์ด** น้ำ · แสง · ดิน + กล่อง "ระวัง" + ลิงก์แหล่งอ้างอิง ป้าย "เฉพาะชนิดนี้" / "ทั่วไปของสกุล"
- ถ้าไม่แน่ใจ: เคล็ดลับถ่ายรูปใหม่ 4 ข้อ
- "ทำไมโมเดลถึงตอบแบบนี้": สกุลที่เป็นไปได้ + ชนิดภายในสกุล + Grad-CAM
- sidebar: เลือกโมเดล 3 ตัว **เรียงตามความแม่น** (1. DenseNet-121 91.0% · 2. EfficientNet-B3 90.4% ·
  3. EfficientNetV2-B0 89.8%) + เทียบผลทั้ง 3 โมเดลพร้อมกัน
- หน้าว่างแสดงวิธีใช้ 3 ขั้น + เคล็ดลับถ่ายรูป · รองรับมือถือ · ไม่เก็บรูปที่อัปโหลด

**หน้า "ประเมินผลโมเดล"** (นำเสนอ)
- แท็บผลลัพธ์: KPI เทียบเป้า 91% และ gap 9.86% · กราฟเทียบ 6 โมเดล (ค่าเฉลี่ย ± SD) · ตาราง + McNemar
  · เจาะรายโมเดล/seed/ชุดข้อมูล/ระดับ: confusion matrix, ความแม่นยำรายคลาส, slider เกณฑ์ความมั่นใจ,
  ภาพที่ทายผิดทั้งที่มั่นใจสูง
- แท็บรายละเอียดโปรเจกต์: โจทย์ ข้อมูล QC โมเดล สูตรเทรน augmentation (คำอธิบาย + ภาพตัวอย่างรายขั้น)
  การประเมินผล ระบบ — ตัวเลขอ่านจากไฟล์ผลจริงอัตโนมัติ

### 9.2 วิธีดูแลแบบ rule-based
- `care_rules/care_rules.json`: **7 สกุล + 14 ชนิด** แต่ละรายการมี น้ำ / แสง / ดิน (สรุป + รายละเอียด) +
  ข้อผิดพลาดที่พบบ่อย + แหล่งอ้างอิง (LLIFLE, NC State Extension, UA Extension ฯลฯ)
- ใช้คำแนะนำของชนิดเมื่อมั่นใจชนิด ≥ 60% ไม่งั้นใช้ของสกุล · คลาส "สปีชีส์อื่น" ใช้ของสกุล
- แปลงฤดูจากแหล่งอ้างอิงเขตหนาวเป็นของไทย: ร้อน/ฝน (มี.ค.–ต.ค.) = ช่วงโต · หนาว (พ.ย.–ก.พ.) = ช่วงพัก
- ตรวจทานเนื้อหากับแหล่งอ้างอิงแล้ว ตัดข้อความที่แหล่งอ้างอิงไม่รองรับออก

## ส่วนที่ 10: ข้อจำกัด และงานต่อ (ควรมีในสไลด์)

**ข้อจำกัด**
- รู้จักแค่ 7 สกุล ถ้าเป็นสกุลอื่น โมเดลจะทายเป็นสกุลที่ใกล้ที่สุด (แต่ความมั่นใจมักต่ำ → ตอบ "ไม่แน่ใจ")
- ภาพจริงจากฟาร์มมีแค่ 107 ภาพ และยังไม่มีเอคคินอปซิส (ต้นน้อยเกิน) ตัวเลขภาพจริงจึงแกว่งได้ ±3 จุด
- ทายชนิดบนภาพจริงยังยาก (68–72%) โดยเฉพาะกลุ่ม "สปีชีส์อื่น" และยิมโนด่าง (ข้อมูลน้อย)
- ชื่อชนิดจาก iNaturalist บางภาพน่าสงสัย (~12 ภาพ) จดหมายเหตุไว้ให้ผู้เชี่ยวชาญตรวจ ยังไม่ได้แก้
- วิธีดูแลยังเป็นร่างที่ทีมเขียนจากแหล่งอ้างอิง ยังไม่ผ่านผู้เชี่ยวชาญด้านพืช
- Gap ของ 4 จาก 6 โมเดลยังสูงกว่างานวิจัยอ้างอิงเล็กน้อย

**งานต่อ**
- เก็บภาพถ่ายเองเพิ่ม (โดยเฉพาะเอคคินอปซิส ยิมโนด่าง) เพื่อลด gap และวัดภาพจริงให้แม่นขึ้น
- เพิ่มสกุลยอดนิยมอื่น (สำรองไว้แล้ว: Cephalocereus, Melocactus) + คลาส "ไม่ใช่กระบองเพชร"
- ทำแอปมือถือ / frontend ใหม่ผ่าน API ที่มีอยู่ · export โมเดลเป็น ONNX ให้เร็วขึ้นบนมือถือ
- ให้ผู้เชี่ยวชาญตรวจวิธีดูแล
